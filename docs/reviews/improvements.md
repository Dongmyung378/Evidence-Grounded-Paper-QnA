# 답변 품질 및 실행 개선 검토

## 적용한 변경

- 분석 작업은 실행 중인 작업을 포함해 최대 16개까지 접수한다. 초과 요청에는
  HTTP 503과 `Retry-After: 5`를 반환한다. 기존 작업 조회와 중복 요청은 계속 처리한다.
- 요청 본문을 재생한 뒤 실제 연결 종료 메시지를 전달하도록 ASGI 미들웨어를 수정했다.
- 답변에 프롬프트 예문, 단순 확인 문구, 질문만 들어 있으면 재시도한다. 재시도도
  실패하면 근거 없는 답변을 보여주는 대신 명시적으로 거부한다.
- 검색 점수가 NaN 또는 무한대이면 답변 근거로 사용하지 않는다.
- 자동 GPU 선택에서 여유 메모리가 부족하거나 CUDA 메모리 할당이 실패하면 CPU로
  전환한다. 실제 1.5B 비교 실행에서 메모리 부족으로 CPU 전환이 이루어졌다.
- 수동 검토 모델 출력의 기본 덮어쓰기를 막고, 판정 파일을 실제 검수한 출력의 SHA-256에
  연결했다. 모델을 다시 실행하면 새로운 답변을 재검수해야 한다.
- 새 확률적 실험은 시드 378을 사용한다. 작성하는 설명과 주석에는 긴 대시 대신
  ASCII 하이픈을 사용한다. 논문 원문과 과거 모델 출력은 그대로 보존한다.

## 답변 생성 비교와 결정

동일한 20개 질문 및 저장된 검색 근거를 사용해 기존 0.5B 모델, 짧은 프롬프트,
1.5B 후보를 비교했다. 생성 과정에는 Gold 답변을 전달하지 않았다.

| 실행 | sufficient | insufficient | 결정 |
|---|---:|---:|---|
| 초기 0.5B 기준선 | 13 | 7 | 역사적 기준선 |
| 0.5B + 짧은 프롬프트 | 10 | 10 | 기존 정답 회귀로 채택하지 않음 |
| 1.5B + 짧은 프롬프트 | 17 | 3 | 한국어 오답과 근거 없는 주장으로 채택하지 않음 |
| 0.5B + 비응답 차단 | 10 | 10 | 안전성 개선으로 적용 |

`sufficient`는 모델 출력 상태이며 정답 판정이 아니다. 예를 들어 1.5B 후보의
`q-034-ko`는 비대수적 경계를 대수적 경계라고 잘못 표현했고, `q-041-ko`는
레이저 테스트 셀이라는 근거 없는 내용을 만들었다. 생성 건수가 늘었다는 이유로
기본 모델을 바꾸지 않았다.

비응답 차단만 적용한 실제 20문항 실행에서는 기존의 명백한 비응답 3개가 모두
차단되었다. 재시도 후에도 답하지 못해 거부가 7개에서 10개로 늘었다. 이는 안전성
개선이며 답변 정확도 향상으로 해석해서는 안 된다. 현재 기본 생성 모델은 0.5B다.

모델 후보: [공식 Qwen 1.5B 모델 카드](https://huggingface.co/Qwen/Qwen2.5-1.5B-Instruct).
후보 모델은 로컬 캐시에 내려받았지만 기본 모델로 활성화하지 않았다.

## 거부 임계값 개선

기존 보정 데이터 40개 답변 가능 질문과 10개 근거 없는 질문을 이용해 임계값을
`-3.0`에서 `-3.35`로 조정했다. 사전 통과는 `37/40`에서 `38/40`으로 늘었고,
보정용 근거 없는 질문 10개와 기존 holdout 10개는 모두 거부했다. Holdout 실제
파이프라인 실행에서 검증 실패에 의한 안전 거부는 없었다.

새로 통과한 `q-031-en`의 실제 답변은 메모리 사용량과 실행 시간 감소, 허용 가능한
정확도를 언급했다. 관련된 답변이지만 Gold의 정확도 손실이 미미하거나 없다는
한정 표현까지 정밀하게 설명하지는 못했다.

현재 사용자 경로는 `config/runtime_qna.json`이 가리키는 검증된 임계값을 사용한다.
이전 거절 설정과 결과는 유지했다. 비응답 차단 20문항 실행은 옛 임계값을 고정한
대조 실험이고, 임계값 변경은 별도 실제 검색/생성 실행으로 검증했다.

기존 보정 및 holdout 세트를 다시 사용한 회귀 검증이다. 새로운 독립 평가에서
일반화 성능을 입증한 결과는 아니다. `q-001-en/ko`는 여전히 사전 거부된다.

## 평가 기록의 한계 수정

수동 판정은 사용자가 직접 수행한 독립적인 사람 평가가 아니라,
어시스턴트가 Gold와 모델 출력을 대조한 판정이다. 문서에 이 점을 명시했다.
20개 레코드에는 같은 질문의 영어/한국어 쌍이 포함되어 독립적인 질문 내용은
13개다. 이 결과를 전체 30편의 정확도나 새로운 논문에 대한 성능으로 확대해서
설명하면 안 된다.

## 검증과 남은 문제

```bash
python -B scripts/evaluate_day33.py
python -B scripts/validate_day33.py
python -B scripts/validate_improvements.py
```

API 및 개선 회귀 테스트는 19개다. 실제 HTTP 업로드/분석도 다시 실행해
10페이지와 40청크, job 완료 및 근거 추적을 검증한다. 모델 비교 원본과 채택/거절
근거는 `data/evaluation/improvement_decision.json` 및 연결된 JSON에 보관한다.
검수된 실험 출력을 덮어쓰면 기존 결정을 재사용할 수 없도록 해시를 검증한다.

생성 답변의 사실 정확도, 특히 한국어 품질은 여전히 운영 수준에 미달한다. 이번
개선으로 모든 품질 문제가 해결되었다고 판단하지 않는다. 독립적인 신규 Gold 질문,
더 나은 생성 방식의 비교, PDF 처리의 강제 시간 제한과 운영용 작업 격리는 남아 있다.

## 로컬 실행 성능 보정

84.52초가 걸린 로컬 거절 사례를 계기로 장치 배치와 반복 생성 비용을 분리해 점검했다.
검색 모델은 CPU에 두고 Qwen 생성 모델에 GPU 메모리를 우선 배정했다. 생성 모델과
업로드 논문의 Dense 인덱스는 분석 중 준비한다. GPU에서는 답변 가능성 회귀를 막기 위해
기존 최대 3회 검증을 유지하고, CPU 대체 실행만 최대 2회와 시도당 완화된 시간 상한으로
제한했다. API와 화면에도 단계별 시간, 장치, 실제 거절 사유를 추가했다.

실제 전체 HTTP 흐름에서 생성 모델은 CUDA를 사용했고 답변은 9.700초에 완료됐다.
세부 측정과 해석 범위는 [로컬 실행 성능 개선](runtime_performance_KO.md)에 정리했다.
