# 로컬 실행 성능 개선

[English](runtime_performance.md) | [한국어](runtime_performance_KO.md)

## 개선 배경

한국어 질문 한 건이 84.52초 걸린 뒤 안전 거절로 끝나는 사례가 있었다. 확인 결과 검색 모델들이 6GB GPU 메모리 대부분을 먼저 사용해 답변 생성 모델이 CPU로 내려갔고, 검증에 실패한 출력을 최대 3번 생성한 것이 원인이었다. 한국어 자체가 직접적인 원인은 아니었다.

## 실행 정책

고정된 기준선 생성 설정은 유지하고 브라우저 실행에만 별도 프로필을 적용했다.

- 다국어 임베딩 모델은 CPU에서 실행한다.
- Cross-Encoder 재정렬 모델은 CPU에서 실행한다.
- Qwen 답변 생성 모델은 메모리가 충분하면 GPU를 사용한다.
- 논문 분석 중 모델과 업로드 논문의 Dense 인덱스를 미리 준비한다.
- GPU 생성은 검토된 384토큰과 최대 3회 검증 기회를 유지한다.
- CPU 대체 실행은 최대 2회, PyTorch 스레드 8개, 시도당 18초의 완화된 시간 상한을 적용한다.
- API는 검색 시간, 생성 시간, 시도 횟수, 생성 장치, 대체 응답 여부, 거절 출처를 반환한다.
- 화면은 실제 거절 사유와 단계별 실행 시간을 표시한다.

기존 `config/generation.json`은 기준선 실험 입력으로 보존했다. 브라우저 서비스는 `config/runtime_qna.json`을 통해 `config/generation_runtime.json`을 읽는다.

## 수용 측정

NVIDIA GeForce RTX 3060 Laptop GPU 6GB 환경에서 시드 378로 실제 HTTP 전체 흐름을 다시 실행했다. `paper-003.pdf`와 기존 영어 HTTP 수용 질문을 사용했다.

| 측정 항목 | 결과 |
|---|---:|
| 분석 중 모델 준비 | 16.692초 |
| 답변 요청 | 9.700초 |
| 검색 | 0.970초 |
| 생성 및 검증 | 8.729초 |
| 생성 시도 | 1회 |
| 생성 장치 | CUDA |
| 답변 결과 | 근거가 충분한 답변, 인용 연결 검증 통과 |

앞선 84.52초 사례와 이번 수용 실행은 논문과 질문이 달라 통제된 전후 비교는 아니다. 이번 결과는 의도한 GPU 배치가 적용되고 기존 답변 가능 통합 질문이 계속 통과한다는 것을 보여준다. 모든 질문의 응답 시간을 보장하는 수치로 사용하면 안 된다.

검증된 한국어 대응 질문 `q-007-ko`도 전체 HTTP 흐름으로 실행했다. 한국어 답변은 9.405초에 근거 충분 상태로 완료됐으며 검색 0.751초, CUDA 생성 8.653초, 생성 1회가 걸렸다. 표현을 바꾼 한국어 질문은 11.893초에 처리됐지만 모델이 보수적으로 거절했다. 따라서 한국어 입력이 84초 지연의 원인은 아니지만, 기존 0.5B 모델의 답변 품질 한계는 여전히 남아 있다.

## 실행 시 주의사항

모델 장치는 로딩 시 결정되므로 실행 설정을 변경한 뒤에는 FastAPI를 다시 시작해야 한다. 다른 프로그램이 GPU 메모리 대부분을 사용하면 생성 모델이 여전히 CPU로 내려가 응답이 느려질 수 있다. 분석 중 준비를 끄려는 경우에만 `PAPER_QNA_PREPARE_MODELS=0`을 사용한다.
