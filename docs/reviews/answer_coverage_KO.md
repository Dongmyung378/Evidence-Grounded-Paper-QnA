# 답변 정보 범위 확장 실험

[English](answer_coverage.md) | [한국어](answer_coverage_KO.md)

핵심 내용 누락을 줄였지만 기본 API에는 적용하지 않았다. 일부 답변의 세부 정보 회귀, 한국어 오역과 추가 계산 비용이 남는다. 개선안은 선택 실행용으로 보존하고 추가 튜닝은 중단했다.

| 동일 실행 비교 | 기준선 | 개선 후보 |
|---|---:|---:|
| 고정 20문항 통과 | 3 | 10 |
| 부분 통과 | 14 | 10 |
| 실패 | 3 | 0 |
| 답변 가능 질문에 답변 | 38/40 | 40/40 |
| 근거 없는 질문 거절 | 19/20 | 20/20 |
| 호스트 답변 단계 평균 | 0.761초 | 2.618초 |

시드는 378이다. 생성 시 Gold는 읽지 않았고 생성 후 고정 20문항을 Gold와 비교했다. 통과는 핵심 내용 포함 여부에 대한 어시스턴트 판정이며 완벽한 표현을 뜻하지 않는다. 독립적인 사람 평가나 새 테스트셋 성능도 아니다. 고정 20문항의 서로 다른 의미는 13개이며 답변 생성 여부는 정답률이 아니다.

후보 시간에는 별도 측정한 문장 재정렬을 합산했다. 검색, 초기화와 HTTP는 제외한다. 검색은 CPU, 번역은 CUDA를 사용했고 실행 순서와 번역 캐시 영향이 있다. Docker CPU 응답 시간이나 속도 개선으로 주장하지 않는다.

## 구현과 한계

- 같은 논문과 페이지의 인접 청크로 잘린 문장을 복원하고 주변 문맥과 함께 재정렬한다. 인용은 최대 5개 원본 청크다.
- 제한된 형식의 논문 주요 문제 질문은 초록을 사용한다. 나머지는 기존 거절 정책에 dense 유사도 확인을 추가한다.
- 원문 문자 범위를 복원 검증한다. 지원되지 않는 숫자나 예상 밖 문자 체계의 번역 문장은 제외하지만 의미 오역을 모두 검출하지는 못한다.

ContCore의 11개 일정과 두 데이터셋, Voronoi의 두 구성, MS-WDRO의 ABIDE I와 7개 기준선을 복원했다. 반면 `q-041-en`에서는 기존의 세 gripper와 성공률 설명이 빠졌다. 한국어 simplex, singular point 등의 오역도 남는다.

dense 임계값 0.78은 재사용한 답변 가능 질문에서 정한 개발 기준이다. 기존 holdout 오류도 확인했으므로 이번 20/20을 독립 테스트 성능으로 제시하지 않는다. 과거 기준선 holdout 기록은 10/10이지만 이번 동일 실행에서는 9/10이었다. 과거 파일은 현재 보장이 아니다.

## 실행과 검증

`GroundedQAPipeline(..., enable_answer_coverage=True)`로 선택 실행한다. 기본값은 `False`이며 UI/API는 기존 방식을 유지한다. `config/answer_coverage.json`은 실험 후보 설정이지 기본 API 활성화 스위치가 아니다. 실제 모델 평가는 독립 실행 스크립트, 런타임 연결은 회귀 테스트로 확인했다. Docker는 재측정하지 않았다.

`python -B scripts/review_answer_coverage.py`는 모델 실행 없이 결과와 출처를 검증한다. 의도적인 재실행에만 `python -B scripts/evaluate_answer_coverage.py --all-questions`를 사용한다.

`data/evaluation/answer_coverage_outputs.json`은 원본 응답, `answer_coverage_review_labels.jsonl`은 문항별 판정, `answer_coverage_review.json`은 집계와 해시다. 원문 연결은 후보 답변 40건에서 검증했지만 의미 검토는 고정 20건에 한정한다.
