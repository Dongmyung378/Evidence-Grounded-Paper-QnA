# 근거 기반 답변 정책

[English](answer_policy.md) | [한국어](answer_policy_KO.md)

이 문서는 기본 근거 기반 답변 경로를 설명합니다. 영어 질문에는 선택한
원문 문장을 인용하는 추출 답변을 제공하고, 한국어 질문에는 같은 문장을
로컬 번역 모델로 번역합니다. 정책은 정답 파일이 아닌 검색된 원문을
사용합니다. 관찰 가능한 오류를 줄이는 검사이며 과학적 사실의 정확성을
보장하지 않습니다. 평가 입력과 집계 기준, 독립 검토 준비는
[최종 답변 품질 평가](quality_benchmark_KO.md)를 참고합니다.

## 처리 순서

검색 점수에 따른 거부 정책을 통과하면 질문에 명시된 전제, 검색 근거와
질문이 요구한 내용의 관련성, 근거 문장 선택, 답변 구성 또는 번역,
최종 응답 검증 순으로 처리합니다. 정책이 거부한 질문에는 인용이 없는
정해진 `insufficient` 응답을 반환합니다. 이 경우 번역 추론은 실행하지
않습니다. 번역 모델의 초기화까지 생략했다는 의미는 아닙니다.

전제 검사나 관련성 정책의 의도적인 거부는 `fallback_used: false`로
기록합니다. 점수 계산 오류, 사용할 수 없는 원문, 답변 검증 실패와 번역
검증 실패는 안전한 거부 응답으로 처리하며 `fallback_used: true`로
기록합니다. 결과 집계에서는 사유 코드와 최종 응답을 함께 확인해야 합니다.

## 질문에 필요한 근거 보존

일반적인 질문 표현을 바탕으로 목록, 비교, 수치, 한계, 평가 방식을
구분합니다. 평가, 검증, 어떤 실험을 사용했는지 묻는 질문은 대상 목록,
기준 모델, 평가 지표와 인식한 조건을 포함할 수 있도록 문장 예산을
확장합니다. 영어와 한국어를 지원하며 단일 방법을 묻는 질문을 자동으로 전체 목록
질문으로 취급하지 않습니다.

일반 질문의 근거 선택에서는 기본적으로 한 페이지당 청크 두 개를
허용합니다. 여러 항목을 다루는 질문 유형에서는 같은 페이지에 필요한
근거가 모여 있을 수 있으므로 설정된 근거 예산까지 선택할 수 있습니다.
유사한 문장이라도 숫자, 기술 식별자, 비교 방향의 표지가 다르면 두 번째
결과를 단순 중복으로 제거하지 않습니다.

기본 검색 근거는 순위와 점수를 보존한 객체 최대 5개입니다. 예측 과제를
명시적으로 묻는 질문에 필요한 일반 서술문이 그 객체에 없으면 같은 논문의
이미 재정렬한 후보 20개에서 전체 원문 청크를 최대 1개만 답변 문맥에
추가할 수 있습니다. 기본 객체를 교체하거나 다시 정렬하지 않으며 새로운
청크를 읽거나 누락된 과제를 만들어 내지 않습니다. 필요한 과제의 근거가
없으면 답변을 거부합니다.

선택기는 `evidence_selection.answer_context_supplements`와
`evidence_selection.answer_context_supplement_origins`에 원래 후보 순위와
원문 해시를 포함한 추가 원문의 기록을 남깁니다. 파이프라인의
`pipeline.evidence_context`에는 `primary_retrieval_count`,
`primary_retrieval_evidence_ids`, `supplement_count`, `answer_context_count`와
`supplement_origins`를 기록합니다. `retrieved_evidence`는 전체 답변 문맥이며
`cited_evidence`는 검증을 통과한 실제 인용만 포함합니다. HTTP `/question`
응답은 실제 인용을 `evidence`로 제공합니다.

문장 선택은 번호가 있는 목록 항목과 제목을 묶고, 인접한 제한 조건이나
평가하지 않은 범위의 부정 표현을 인식하면 함께 보존합니다. 인접 문장은
제공된 같은 근거 기록 안에 실제로 있어야 합니다. 검색되지 않은 청크를
새로 읽거나 누락된 항목을 만들어 내지 않으며 근거 ID를 변경하지 않습니다.
예산을 맞추기 위해 묶음의 제한 조건만 조용히 제거하지 않습니다.
문장 수와 문자 수의 제한은 계속 적용됩니다.

현재 원문 문장의 초기 선택 한도는
[answer_generation.json](../config/answer_generation.json)에 정의되어 있습니다.

| 질문 유형 | 영어 원문 문장 수 | 한국어 원문 문장 수 |
| --- | ---: | ---: |
| 기본 | 3 | 2 |
| 목록 | 8 | 8 |
| 비교 | 4 | 4 |
| 수치 | 3 | 3 |
| 한계 | 4 | 4 |
| 평가 방식 | 4 | 4 |

인접 조건의 묶음을 유지하기 위해 최종 답변 한도 안에서 초기 선택 문장이
늘어날 수 있습니다. 예산은 완전한 답변을 보장하는 수치가 아닙니다. 기본
검색 근거는 최대 5개이고 제한된 추가 원문을 포함한 답변 문맥은 최대
6개이며 인용은 계속 최대 5개입니다. 선택 문장은 최대 여덟 개를 사용합니다.
검색이 필요한 사실을 놓치거나 원문 추출 결과에서 불완전한 문장이 제외될
수 있습니다.
평가 질문에서는 인식한 평가 단서가 있는 문장을 중심으로 인접 조건을
보존합니다. 이런 중심 문장이 있으면 관련 없는 방법 설명이나
하이퍼파라미터 문장으로 남은 예산을 채우지 않습니다. 네 문장 예산에서도
실제 관련 실험 문장 두 개만 답변에 사용할 수 있습니다. 단서의 문자열
일치는 문장이 질문에 답한다는 의미적 증명이 아닙니다.
원문에서 추출한 절 제목이 본문에 붙어 남는 경우도 있습니다. 현재 제목
정리 규칙이 모든 형태의 헤더 잡음을 제거하지는 않습니다.

## 번역과 최종 출력 검증

기본 로컬 번역 경로는 원문 입력마다 비어 있지 않은 출력을 하나씩
요구합니다. 각 번역을 해당 원문과 개별 비교하므로 두 문장의 숫자를
맞바꿔도 전체 숫자 집합이 같다는 이유로 통과하지 않습니다.

- `1.0 = 1`, `1e-3 = 0.001`처럼 동치인 수치를 표준화합니다.
  지원하는 규모 표현과 퍼센트, 배율 표기도 유지합니다.
- 일반적인 측정 단위의 동일성을 검사합니다. `second`와 `초`처럼
  등록된 표기 대응을 허용하지만 임의의 단위 환산을 구현한 것은 아닙니다.
- 인식한 영문 기술 식별자가 번역에 남아 있는지 확인합니다.
  로컬 어댑터가 원문에서 보호한 약어, CamelCase 이름과 모델 식별자를
  복원한 뒤 검사합니다. 보호한 표현이 누락되면 질문이나 정답에서
  추측해 채우지 않고 번역을 거부합니다.
- 명시적인 부정과 범위 한정의 표지를 보수적으로 검사합니다.
  원문의 `not`, `cannot`, `only`에 대응하는 한국어 표현으로
  `않습니다`, `없습니다`, `오직`, `에만`, `에서만`, `뿐`, `불과`, `유일`, `단지` 등을
  허용합니다. 한정 표현인 `단`과 `단계` 같은 단어를 구분하며 상한,
  하한과 예외 표지도 따로 검사합니다. `not only`는 일반 부정으로
  처리하지 않습니다.

이 검사는 관찰 가능한 표지를 확인하는 규칙입니다. 번역의 전체 의미
동치를 판단하는 모델이 아닙니다. 숫자나 부정 단어가 모두 남아 있어도
문장의 의미가 틀릴 수 있으며, 올바른 의역이 등록된 표현을 사용하지
않으면 거부될 수 있습니다. 모든 부정의 적용 대상, 암묵적인 조건,
수량과 대상의 연결, 기술 이름의 음역을 해결하지 않습니다.

[원문 기반 전문용어집](../config/translation_glossary.json)은 개발용 출력에서
확인한 `robot gripper`의 `로봇 지갑` 오역과 `ground truth`의 `토지 진실`
오역에 대응합니다. `robot gripper`는 `로봇 그리퍼`, `ground truth`는
`참값`으로 대응하며 `ground-truth labels`의 `정답 레이블`처럼 더 긴
등록 표현을 먼저 적용합니다. 영문 대소문자를 구분하지 않고 단어 경계를
확인하며 선택된 원문 문장에 해당 표현이 있을 때만 적용합니다. 용어집의
복원 단계에서 원문에 없는 용어, 모델명, 설명이나 수치를 추가하지 않습니다.
일반 학습 용어에는 `weight decay`의 `가중치 감쇠`, `temperature scaling`의
`온도 보정`, `confidence calibration`의 `신뢰도 보정`과 자기지도 학습,
대조 학습, 데이터 증강, 지식 증류의 등록 표현도 포함합니다. 개발용
원문에서 관찰한 용어를 보완한 것이며 새로운 논문의 번역 품질을 입증하지 않습니다.
대조 예측 과제, 가우시안 블러, 무작위 자르기, 색상 왜곡과 사전학습
과제도 구분합니다. 보정 관련 명사, 동사와 형용사 형태를 각각 등록하고
`not calibrated` 같은 긴 표현을 우선합니다. 전문용어가 복원됐다는
이유로 문장 안의 의미 연결이나 한국어 활용이 자연스럽다고 보장하지는 않습니다.

[로컬 어댑터](../scripts/local_translation.py)는 NLLB 추론 전에 등록 용어와
기술 식별자, 두 단어 이상이 대문자로 시작하는 영문 이름을 보호합니다.
`Shadow Hand`는 논문별 이름 목록 때문이 아니라 원문에 있는 표기를
인식해 보호합니다.
`dataset`, `benchmark`, `corpus` 앞에서 데이터 자원 이름으로 명시된
한 단어 이름도 원문 표기를 보호합니다. 표면적인 형태를 보는 규칙이므로
대문자로 시작하는 일반 명사를 이름으로 잘못 인식할 수 있습니다.
같은 번역 배치에 실제 제공된 다른 문장이 데이터 자원 이름을 명시하면
그 이름이 해당 배치의 다른 원문에 등장할 때도 정확한 표기를 보호합니다.
논문 이름 목록이나 외부 개체 정보는 사용하지 않습니다. 영문 단어 사이
쉼표나 세미콜론 뒤에 빠진 공백은 보호 전에 복원하며 숫자 구두점과
인식된 URL은 유지합니다. 이 정리는 원문 절을 삭제하거나 다시 쓰지 않습니다.
같은 표현이 반복돼도 각 위치에 별도의 `ZXQAAA` 같은
알파벳 표지를 부여해 새로운 숫자를 만들지 않습니다. 출력은 모든 표지를
정확히 한 번씩 유지해야 하며 누락, 중복, 변형이나 알 수 없는 표지는
거부합니다. 검사 후 등록된 한국어 용어나 원문의 정확한 영문 이름을
복원합니다. 약어로도 인식되는 전체 대문자 용어는 원문 표기를 괄호에
함께 유지합니다. 일부 한국어 조사는 복원된 명사의 받침에 맞추며 영문
이름의 조사는 변경하지 않습니다. 일반 숫자는 모델 입력에 그대로 남겨
둡니다. 숫자가 직접 쓰인 퍼센트 범위 표현은 관계 단어만 표지로 보호하며
수치와 퍼센트 표기는 모델 입력에 남겨 둡니다.
`below 1%`는 `1% 미만`, `at most 1%`는 `1% 이하`로 복원해 원문에
명시된 엄격성, 비교 방향과 숫자 표기를 유지합니다. 복원 시 표지와 바로
인접한 동치 퍼센트 수치만 중복을 제거합니다. 다른 수치나 중간에 관계
표현이 있는 수치는 제거하지 않으며 표지 양쪽에 수치가 있으면 모호한
출력으로 거부합니다. `percent`와 `%`는
동치 표기로 대응하며 원문에 없는 수치를 추정하거나 계산하지 않고
임의의 단위 전체를 해석하지 않습니다. 복원 후 기존 수치, 단위와
숫자 범위 검증을 모두 적용합니다. 번역되지 않은 CJK 문자나
영어 서술을 그대로 복사한 출력도 캐시에 저장하기 전에 거부합니다.
용어 복원만으로 한국어가 생긴 영어 서술 복사도 거부하며 영문 이름이나
수치만 있는 부분 목록은 허용합니다. 전체 답변은 이후 언어 검증을
거칩니다. 새 번역 중 하나라도 실패한 배치는 캐시에 새 항목을 저장하지 않습니다.

입력을 조용히 잘라 번역하지 않습니다. 설정된 입력 토큰 예산을 넘으면
거부하고 출력 마지막에 종료 토큰이 없는 경우도 거부합니다. 종료 토큰이
있다는 이유로 모든 원문 절이 번역됐다고 보장하지는 않습니다. 모델이
일찍 문장을 끝내거나 검사 규칙이 인식하지 못하는 조건을 누락하면
통과할 수 있습니다. 미등록 용어, 데이터 자원 문맥 밖의 한 단어 이름이나
인식 범위 밖의 이름은
여전히 오역될 수 있고 보호 표지 복사에 실패하면 번역을 거부합니다.
전문용어 전체의 정확성, 자연스러운 문장이나 완전한 의미 동치를
보장하는 기능은 아닙니다.

기본 번역은 하나의 추론 후보를 사용하는 결정적 방식입니다.
[translation.json](../config/translation.json)의
`retry_on_validation_failure: true`, `retry_num_beams: 2` 설정을 사용하면
표지 복원, 언어 검사나 원문 검증에 실패한 문장에 한해서 같은 보호 입력을
두 후보로 한 번만 다시 번역합니다. 기존 검증은 그대로 적용합니다.
토큰 예산, 모델 배치 개수와 같은 구조적인 오류에는 재시도하지 않으며
재시도 설정이 없는 과거 설정은 기존 한 번의 추론을 유지합니다.
재시도에도 용어나 한정 표현이 빠지면 거부합니다.
`metadata()['validation_retry']`에서 누적 시도, 검증을 통과한 복구,
실패 횟수와 최근 요청이 사용한 후보 수를 확인할 수 있습니다. 복구 횟수는
개별 문장 기준이며 다른 문장의 실패로 배치 전체가 실패하면 새 캐시는
저장하지 않습니다. 재시도 시간도 번역 지연에 포함하며 일반적인 속도
향상을 보장하는 기능은 아닙니다.

`TranslationFidelityError.translation_diagnostics`는 가능한 경우 원문,
보호한 입력, 잘못된 모델 출력, 복원 출력과 실패 단계를 길이를 제한해
보관합니다. 명시적으로 요청한 개발용 진단 출력에서만 사용하며 일반
오류 메시지와 거부 응답에는 잘못된 번역을 공개하지 않습니다. 원문 정리,
용어집이나 검증 변경을 측정할 때는 해당 코드 보존본과 실제 개발용
모델 출력을 별도로 남겨야 합니다.

어댑터는 검증을 통과한 문장을 프로세스 내부의 제한된 LRU 캐시에
보관합니다. 기본 용량은 128개이며 최대 256개까지 설정할 수 있고
용량 0은 캐시를 끕니다. 키에는 정확한 원문, 모델 revision, 번역 설정과
용어집의 fingerprint, 보호 정책 버전과 해당 입력에 실제 등장하는
배치 내 명시 이름 맥락이 포함됩니다. 현재 이름 보호 맥락 없이 만든
번역을 잘못 재사용하지 않도록 구분합니다. 같은 배치의 중복
입력은 한 번만 추론하면서 요청한 출력 순서를 유지합니다.
`clear_cache()`로 번역 캐시를 비울 수 있으며 `metadata()['cache']`에서
적중, 미적중, 크기, 용량, 제거 횟수와 배치 내 중복 횟수를 확인할 수
있습니다. 반복 문장을 캐시에서 반환한 시간은 새로운 번역 추론 시간이
아닙니다. 새 추론의 지연은 캐시를 끄거나 비우고 모델 초기화 시간을
제외한 동일한 조건에서 비교해야 합니다.
[번역 충실도 테스트](../tests/test_translation_fidelity.py)는 모델을 다운로드하지
않고 복원 실패, 수치와 한정 표현 변조, 토큰 예산과 캐시 용량을 검증합니다.

최종 검증은 숫자의 근거 존재 여부, 답변 길이, 언어, 응답 형식과 인용 ID도
확인합니다. 유효한 ID는 원문 위치를 확인할 수 있다는 뜻이며 모든 주장이
완전하게 뒷받침된다는 뜻은 아닙니다. 검증에 실패한 번역은 답변으로
공개하지 않고 정해진 거부 응답으로 처리합니다.

## 질문에 명시된 전제 검사

문장 선택 전에 검색된 전체 근거와 질문의 전제를 비교합니다. 근거에 없는
퍼센트, 배율, 측정값이나 명시적인 개수를 전제한 질문은 거부합니다.
수치가 얼마인지 묻거나 세 가지 입력을 나열해 달라는 요청 자체를 관찰된
측정값의 주장으로 취급하지 않습니다.

질문이 모델, 방법, 데이터셋을 명시적으로 지시하면 영문 식별자의 근거
존재 여부를 확인합니다. 일반적인 한국어 이름 음역을 영어 철자와 정확히
일치시키도록 요구하지 않습니다. 전 세계 모든 대상과의 비교 주장은
명시적인 세계 전체 표현과 비교 표현이 함께 있어야 범위 검사 대상이
됩니다. `global average pooling`, 예 또는 아니오 질문의 `any`, 유한한
`global benchmark`에서 평가한 모든 기준 모델은 이 범위 규칙으로
거부하지 않습니다.

“정확도가 99%인가요?”처럼 검증되지 않은 수치를 묻는 질문은 수치를
정정하는 설명 대신 보수적으로 거부할 수 있습니다. 이 검사는 검색된
근거에서 전제를 확인하지 못했다는 의미입니다. 전체 논문에서도 전제가
거짓이라고 증명하거나 인과 설명을 검증한 것은 아닙니다.

## 논문 이름의 편향을 줄인 답변 가능성 검사

[answerability_policy.py](../scripts/answerability_policy.py)는 제공된 원문에서
제목이나 모델 지시 문맥과 함께 반복되는 이름을 주제 표지로 인식합니다.
`source_derived_topic_debias_v2` 변환은 질문의 문법을 유지하면서 인식한
이름이 포함된 제목 표현을 일반적인 주어로 바꿉니다. 근거의 점수 계산용
사본에서도 같은 표지를 가리고 과학적 대문자 약어는 유지합니다.
초점을 좁힌 질문은 수단을 설명한 절을 제거하되 요청한 결과는 남깁니다.
원래 질문과 원문 근거는 변경하지 않습니다.

고정 리비전의 재순위화 모델로 변환한 전체 질문과 요청 내용에 초점을
맞춘 질문을 각각 모든 근거 항목과 비교합니다. 질문별로 가장 높은 근거
점수를 구한 뒤 두 최댓값 중 작은 값을 사용합니다.

```text
aspect_score = min(max(score(full_question, evidence_i)),
                   max(score(focused_request, evidence_i)))
```

두 질문이 같으면 한 번만 계산합니다. 작은 값을 사용하는 이유는 관련
수단이나 방법의 이름이 요청한 결과의 근거를 대신하지 않도록 하기
위해서입니다. 구체적인 요구 내용이 남지 않으면 이 점수만으로 거부하지
않습니다. 점수가 없거나 유한하지 않으면 답변을 뒷받침하는 점수로 사용할
수 없습니다.

[answerability_policy.json](../config/answerability_policy.json)의 현재 임계값은
`-3.405527949333191`이며 점수가 이 값 이상이면 점수 조건을 통과합니다.
[v2 보정 보고서](../data/quality_benchmark/runs/2026-10-10-v2/answerability-dev-calibration.json)는
**가상 DEV 언어 사례 20개인 정상 질문 다섯 의미 그룹과 근거 없음 또는
거짓 전제 다섯 의미 그룹**에 더해 **기존에 개발 자료로 선언한 실논문
DEV 18개를 답변 유지 제약**으로 사용합니다. 추가 자료는 개발 입력이며
독립 평가가 아닙니다. 원래 실논문 부분집합 20개 중 `q-001-en`과
`q-001-ko`는 변경하지 않은 전체 검색 임계값 `-3.35`에서 이미 거부되므로
제약에서 제외했습니다. 이번 추가 검사는 이 두 오거부를 복구하지 않습니다.

보정 당시 선택한 임계값은 가상 정상 다섯 그룹과 추가 유지 사례 18개를
모두 유지하면서 부정 사례 다섯 그룹 중 네 그룹을 거부했습니다. 두 언어
변형은 의미 그룹으로 묶으며 독립 사례가 두 배 늘어난 것으로 해석하지
않습니다. 관련성 임계값과 보정 당시 결합 정책 모두 DEV 그룹을 완전히
구분하지 못합니다.

[보정 당시 정확한 원본](../data/quality_benchmark/runs/2026-10-10-v2/calibration-sources/scripts/answerability_policy.py)의
SHA-256은
`e8d552fe78f40d435789b57772f0dd5f9fff8b54e28aa24efc28983730b55a6b`입니다.
현재 실행 코드는 이 원본과 다릅니다. 보정 후 정책 검사에서는 PDF 합자와
줄바꿈 오류를 정규화하고, 문맥으로 임상 결과와 연구 참여 집단을 인식하며,
두 언어의 개인정보 보호 요청을 확인하고 요청한 측정 단위를 무관한 개수와
구분하도록 보완했습니다. 구성요소 사용이나 성능 향상을 단정한 질문은
일치하는 원문 관계가 그 사용을 부정하거나 속성이 유지된다고 밝힐 때
거부합니다. 중립적 질문과 부정형 질문은 보호합니다.

이 변경은 초기 실논문 DEV 출력을 포함한 공개된 개발 근거에서 보완한
결정적 규칙입니다. 점수용 질문 구성, 점수 산식과 임계값을 변경하지
않았으며 이 추가 규칙을 위해 모델로 다시 보정하지 않았습니다. 단위
테스트와 저장된 근거의 기능 검사는 최종 모델 정확도를 입증하지 않습니다.
이미 공개한 합성 HOLDOUT 실패는 이제 개발 자료입니다. 새 실논문
HOLDOUT은 별도로 유지하고 실행 전에 코드를 고정해야 합니다.

이 보정은 제한적인 모델 연결과 개발 자료의 답변 유지를 확인합니다.
관련성 점수는 정답 확률이나 의미적 뒷받침의 증명이 아닙니다. 개념 존재
여부와 전제 검사는 제한된 휴리스틱이며 다른 표현이나 필요한 문맥을
놓칠 수 있습니다. 오거부와 근거 없이 유지된 답변을 최종 출력에서
검토해야 합니다. 별도로 기록한 실논문 평가 상태는
[완료 평가](completion_evaluation_KO.md)를 참고합니다. 이 보정 결과를
독립적인 실논문 의미 정확도로 해석하면 안 됩니다.

## 기록 확인과 검증

내부 결과에는 관련성 판단, 점수, 임계값과 정책 지문을 기록합니다.
시간 측정은 문장 선택, 답변 구성, 번역, 검증으로 나눕니다. 관련성 점수
계산은 문장 선택 시간에 포함하고 전제 검사는 검증 시간에 포함합니다.

테스트 의존성을 설치한 뒤 저장소 루트에서 실행합니다.

```bash
python -m unittest discover -s tests -p test_answer_completeness.py -v
python -m unittest discover -s tests -p test_grounded_generation.py -v
python -m unittest discover -s tests -p test_answerability_policy.py -v
```

단위 테스트와 가상 자료 보정은 독립 검토, 제3자 재현 검증이나 프로젝트
개선 계획의 완료를 의미하지 않습니다. 새 실제 논문 입력을 고정하고 최종
출력을 평가한 뒤 사실 정확성, 완전성, 인용 뒷받침의 검토자와 판정 근거를
기록하는 절차는 [품질 평가 문서](quality_benchmark_KO.md)를 따릅니다.
기존 동결 결과는 당시 구현의 측정 기록이며 이 정책의 측정값으로
바꿔 설명하면 안 됩니다.
