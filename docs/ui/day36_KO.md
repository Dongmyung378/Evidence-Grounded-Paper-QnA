# 36일차 Streamlit UI

[English](day36.md) | [한국어](day36_KO.md)

## 원 계획 기준

- 작업: PDF 업로드, 분석 상태, 논문 개요, 질문 입력 화면 구현
- 완료 기준: 사용자가 브라우저에서 PDF를 업로드한다.

## 구현 내용

`ui/app.py`의 Streamlit 화면이 `ui/api_client.py`를 통해 기존 FastAPI 서비스와 통신한다. 화면 로직과 파싱, 검색, 답변 생성 코드를 분리해 기존 백엔드 흐름을 그대로 재사용한다.

36일차 화면에는 다음 기능이 포함된다.

- 영어와 한국어 화면 전환
- 브라우저에서 PDF 한 편 업로드, 최대 20 MiB
- 분석 대기, 진행, 완료, 실패 상태 표시
- 전체 페이지, 텍스트 페이지, 청크, 경고 수 표시
- 추출한 초록과 식별한 절 제목 표시
- 분석 완료 전까지 비활성화되는 질문 입력란
- 기존 API를 통한 질문 전송, 답변, 거절 사유, 단계별 실행 시간 표시
- 연결, 파일, 분석 오류를 위한 사용자용 메시지

근거 원문, 페이지, 절을 함께 보여주는 상세 화면은 원 계획상 37일차 작업이다. 36일차 UI는 API 근거 계약과 고정 검색 평가 결과를 변경하지 않는다.

## 로컬 실행

의존성을 한 번 설치한다.

```bash
python -m pip install -r requirements.txt
```

첫 번째 터미널에서 FastAPI를 실행한다.

```bash
python -m uvicorn app.main:app --host 127.0.0.1 --port 8000 --workers 1
```

두 번째 터미널에서 Streamlit을 실행한다.

```bash
python -m streamlit run ui/app.py
```

브라우저에서 `http://127.0.0.1:8501`을 연다. FastAPI 주소가 다르면 화면 왼쪽 설정이나 `PAPER_QNA_API_URL` 환경변수에서 변경할 수 있다.

## 검증 결과

실제 로컬 FastAPI 서버와 Streamlit 서버를 실행하고 헤드리스 Microsoft Edge로 수용 테스트를 수행했다. 브라우저에서 `paper-003.pdf`를 선택하고 업로드와 분석 버튼을 누른 뒤 논문 개요와 질문 입력란이 나타날 때까지 확인했다.

| 검증 항목 | 결과 |
|---|---:|
| 회귀 및 UI 테스트 | 33개 통과 |
| 브라우저 PDF 업로드 | 통과 |
| 분석 상태 완료 | 통과 |
| 처리한 논문 | 10페이지, 40청크 |
| 논문 개요 표시 | 통과 |
| 분석 후 질문 입력 활성화 | 통과 |
| 분석 중 질문 모델과 인덱스 준비 | 통과 |
| 시드 | 378 |
| 고정 평가 입력 변경 | 없음 |
| 임시 런타임 잔존 | 없음 |

저장된 결과는 다음 명령으로 검증한다.

```bash
python -B scripts/validate_day36.py
```

전체 기계 판독 결과는 `data/evaluation/day36_ui_results.json`에 있다. 자동 브라우저 평가기는 `scripts/evaluate_day36.py`이며, 다시 실행하려면 애플리케이션 의존성 외에 Node.js, Playwright, 로컬 Chromium 브라우저가 필요하다.

## 완료 판단

36일차는 원 계획의 완료 기준을 충족했다. 사용자는 브라우저에서 텍스트 기반 영어 PDF를 업로드하고 분석 상태를 확인한 뒤 논문 개요와 활성화된 질문 입력란까지 사용할 수 있다. 이 평가는 UI 기능 통합에 대한 판단이며, 32일차에 확인한 답변 품질 한계를 변경하지 않는다.
