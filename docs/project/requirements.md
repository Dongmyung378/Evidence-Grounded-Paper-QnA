# 기능 및 비기능 요구사항

## FR-01 PDF 업로드

- PDF 파일 한 편만 받는다.
- 최대 20 MiB를 허용한다.
- 빈 파일, 손상 파일, 암호화 파일, 텍스트가 없는 파일, PDF가 아닌 파일을 거부한다.
- 성공 시 고유 `paper_id`를 발급하며 실패 중 생성한 파일은 제거한다.

## FR-02 텍스트 파싱

- 페이지별 텍스트와 페이지 번호를 추출한다.
- 각 페이지와 청크에 고유 식별자를 부여한다.
- 가능한 경우 절 정보를 저장한다.
- 모든 청크는 원본 페이지로 역추적할 수 있어야 한다.
- 부분 파싱 실패를 전체 성공으로 보고하지 않는다.

## FR-03 논문 개요

- 제목, 초록, 주요 절을 제공한다.
- 추출할 수 없는 항목은 명확하게 표시한다.
- 이미지, 그래프, 수식을 이해했다고 주장하지 않는다.

## FR-04 다국어 질문과 답변

- 한국어와 영어 질문을 받는다.
- 영어 논문에서 다국어 검색을 수행한다.
- 질문 언어로 답한다.
- 현재 선택한 논문 한 편의 근거만 사용한다.
- 근거가 부족하면 답변을 거절한다.

## FR-05 근거 검색

- BM25, Dense, Hybrid 검색을 지원한다.
- 검색 후보를 점수 순으로 반환한다.
- 근거마다 페이지, 절, 청크 식별자, 영어 원문을 포함한다.

## FR-06 재정렬

- 다국어 Cross-Encoder로 초기 후보를 재정렬한다.
- 동일한 평가 세트에서 기준 검색과 비교한다.
- 재정렬 모델 미세조정은 MVP 필수 조건이 아니다.

## FR-07 근거 기반 답변 생성

- 선택한 근거만 언어 모델에 전달한다.
- 답변에 실제 제공된 근거 식별자만 포함한다.
- 답변 언어가 질문 언어와 같아야 한다.
- 근거 없는 사실을 생성하지 않고 부족할 때 명시적으로 거절한다.

## FR-08 답변 거절

- 논문에 없거나 외부 지식이 필요한 질문을 거절한다.
- 질문 언어로 검증 불가능 이유를 제공한다.
- 거절 응답은 빈 `evidence_ids`와 비어 있지 않은 `abstention_reason`을 가진다.

## FR-09 단일 논문 격리

- 질문은 지정한 `paper_id`의 논문만 검색한다.
- 서로 다른 논문의 페이지, 청크, 인덱스를 섞지 않는다.
- 논문 간 비교는 수행하지 않는다.

## FR-10 실행 및 배포

- FastAPI로 백엔드를 실행한다.
- 기본 상태 확인 API를 제공한다.
- 간단한 웹 UI, Docker 실행, 공개 URL 배포가 가능해야 한다.
- 비밀 값과 환경별 설정은 코드에 직접 넣지 않는다.

## 비기능 요구사항

### 재현성

- 모델 이름과 정확한 리비전을 기록한다.
- 검색 및 생성 설정을 파일로 보존한다.
- 확률적 작업은 시드 378을 사용한다.
- 결과 파일은 사용한 설정과 구현 SHA-256을 기록한다.

### 오류 처리

- 사용자 응답에 내부 경로와 스택 추적을 노출하지 않는다.
- 파싱, 검색, 모델 오류를 안정적인 HTTP 오류 계약으로 변환한다.
- 작업 재시작과 실패 후 재시도를 지원한다.

### 평가

- BM25, Dense, Hybrid, Hybrid + 재정렬을 비교한다.
- Recall@1, Recall@5, Recall@10, MRR을 기록한다.
- 인용 정확성, 답변 품질, 거절 성능을 별도로 평가한다.
- 검색 지표를 답변 정확도처럼 표현하지 않는다.

### 보안과 개인정보

- API 키를 하드코딩하지 않는다.
- 업로드 파일을 기본적으로 공개하지 않는다.
- 형식 및 크기 제한을 요청 본문 경계에서 강제한다.
- 더 이상 필요하지 않은 임시 업로드를 제거한다.

## Dense 검색 구성

- 모델: `intfloat/multilingual-e5-small`
- Query 접두사: `query:`
- Passage 접두사: `passage:`
- 평가: 페이지 기준 Recall@1/5/10과 MRR

## 운영 검색 구성

- 모든 운영 검색 설정은 `config/production_retrieval.json`에서 읽는다.
- API와 CLI는 `ProductionRetrieval`을 호출한다.
- 검증된 40문항과 논문 001-010의 지표만 정확도 주장에 사용한다.
- 논문 011-030은 Gold 근거를 만들기 전까지 강건성 검증에만 사용한다.
- 설정 변경 시 전후 지표를 저장하고 기존 Top-5 정답을 잃지 않아야 한다.

## 근거 기반 답변 계약

- 모델 출력은 정확히 `answer`, `evidence_ids`, `sufficiency`, `abstention_reason`을 가진다.
- `sufficiency`는 `sufficient` 또는 `insufficient`만 허용한다.
- 충분한 답변은 제공된 근거에서 고유 식별자 1개부터 5개를 인용한다.
- 부족한 답변은 근거를 인용하지 않고 질문 언어의 거절 답변을 제공한다.
- 근거 내부 문장은 신뢰할 수 없는 자료로 취급하며 시스템 지시를 덮어쓸 수 없다.
- JSON Schema는 `config/answer_output_schema.json`이다.

## 로컬 Q&A 연결

- 실행 흐름은 query -> production retrieval -> reranker -> evidence selection -> local LLM -> answer validation이다.
- 기본 생성 모델은 정확한 리비전으로 고정한 `Qwen/Qwen2.5-0.5B-Instruct`이다.
- 생성은 결정론적으로 실행하고 CUDA 사용이 불가능하면 CPU로 전환한다.
- 생성 단계에 Gold 답변과 Gold 근거를 전달하지 않는다.
- 잘못된 모델 출력은 제한 횟수 재시도 후 안전한 거절로 바꾼다.

## 답변 거절 정책

- 검색 뒤 생성 전에 보정된 거절 정책을 실행한다.
- 빈 후보와 근거 또는 기준 미만의 재정렬 점수는 모델을 호출하지 않고 거절한다.
- 보정 세트와 홀드아웃 세트를 분리한다.
- 홀드아웃 비정답 질문 10개를 모두 거절해야 한다.
- 검증된 정답 가능 질문 유지율은 90% 이상이어야 한다.

## 수동 Q&A 검토

- 사실, 수치, 비교, 한계 질문을 각 5개씩 총 20개 검토한다.
- 영어 10개와 한국어 10개를 포함하고 검증 논문 10편을 모두 다룬다.
- 생성 실행에는 Gold 데이터를 사용하지 않는다.
- 정답 의미, 인용 지지 여부, 언어 일치를 분리해 판정한다.
- 엄격 실패를 최소 5개 기록한다.
- 완료는 평가 자료 구축을 뜻하며 배포 수준 품질을 뜻하지 않는다.

## 업로드와 분석 API

- `POST /upload`는 PDF 한 편을 등록하고 201을 반환한다.
- `POST /analyze`는 비동기 작업을 만들고 202와 상태 위치를 반환한다.
- `GET /jobs/{job_id}`는 안전한 작업 상태를 반환한다.
- SQLite 영속화, 단일 분석 작업자, 중복 요청 재사용, 재시작 복구를 지원한다.
- 업로드 논문의 페이지와 청크는 고정 벤치마크와 분리한다.

## 질문과 결과 API

- `GET /health`는 서버와 질문 엔진 상태를 반환한다.
- `GET /papers/{paper_id}`는 처리 상태, 개요, 페이지 및 청크 수를 반환한다.
- `POST /question`은 분석 완료 논문에만 실행한다.
- 질문 경로는 고정 운영 검색, 재정렬, 근거 선택, 거절 정책, 로컬 생성을 재사용한다.
- 인용 근거는 현재 업로드 논문의 런타임 청크로 해석되어야 한다.

## 전체 API 통합

- UI 없이 실제 TCP HTTP 서버에서 전체 흐름을 실행한다.
- PDF -> parse -> index -> question -> answer가 한 번에 성공해야 한다.
- 업로드 201, 분석 202, 질문 200과 작업 완료를 검증한다.
- 페이지, 청크, 인용의 양방향 추적성을 확인한다.
- 고정 코퍼스와 평가 입력을 변경하지 않고 임시 런타임을 제거한다.

## Streamlit UI

- 브라우저에서 텍스트 기반 영어 PDF 한 편을 업로드할 수 있어야 한다.
- 분석의 대기, 진행, 완료, 실패 상태를 화면에 표시한다.
- 분석이 끝나면 페이지와 청크 수, 초록, 식별한 절을 보여준다.
- 질문 입력은 분석 완료 후에만 활성화한다.
- 화면 언어는 영어와 한국어를 지원하고 API 오류를 사용자용 메시지로 변환한다.
- 실제 브라우저에서 업로드부터 개요와 질문 입력까지 검증한다.
- 답변과 근거 패널을 나란히 배치한다.
- 인용한 각 근거에 순번, 페이지, 절, 논문 원문, 청크 ID를 표시한다.
- 근거가 부족한 답변에는 근거 카드를 만들지 않고 거절 사유를 표시한다.
- 실제 브라우저에서 업로드, 분석, 질문, 답변, 근거 표시까지 검증한다.

## 업로드 오류와 복구

- 최대 허용 크기는 20 MiB이며 화면과 API에서 동일하게 강제한다.
- 크기 초과, PDF가 아닌 파일, 손상 PDF는 분석 전에 명확한 한영 메시지로 차단한다.
- 파싱 실패 시 진행 표시를 오류 상태로 종료하고 실패 원인과 재시도 방법을 보여준다.
- 알 수 없는 백엔드 오류는 내부 메시지를 노출하지 않고 안전한 일반 메시지로 바꾼다.
- 실패 후 파일 선택과 업로드 버튼을 다시 사용할 수 있어야 한다.
- 실제 브라우저에서 크기 초과, 잘못된 PDF, 파싱 실패 후 정상 PDF 재시도까지 검증한다.

## 로컬 실행 성능

- 6GB GPU 환경에서는 임베딩과 재정렬 모델을 CPU에 두고 생성 모델의 GPU 메모리를 확보한다.
- 운영 서버는 논문 분석 중 검색 인덱스와 생성 모델을 준비한다.
- GPU 생성은 기존 최대 3회 검증을 유지하고 CPU 대체 실행만 최대 2회로 제한한다.
- CPU 대체 생성에는 시도당 완화된 시간 상한과 명시적인 스레드 수를 적용한다.
- 질문 API는 검색과 생성 시간, 시도 횟수, 실행 장치, 대체 및 거절 상태를 반환한다.
- 화면은 일반적인 근거 부족과 생성 검증 실패를 실제 거절 사유로 구분해 보여준다.
