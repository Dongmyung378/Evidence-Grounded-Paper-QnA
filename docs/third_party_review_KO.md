# 외부 재현과 답변 검토

[English](third_party_review.md) | [한국어](third_party_review_KO.md)

이 문서는 개발자의 자동 검사와 별도로 다른 사람이 설치와 실행 결과를
확인할 때 사용하는 절차입니다. 새 환경에서 실행한 개발자의 검사나 다른
자동 에이전트의 검토는 외부 사용자 검증을 대신하지 않습니다.

## 실행 준비

저장소의 README에 따라 Python 가상 환경 또는 Docker Compose를 사용합니다.
모델은 고정 리비전을 내려받으며 첫 실행에는 다운로드와 모델 초기화
시간이 필요합니다. 이미 받은 모델만 사용할 때는 오프라인 옵션을
사용합니다. NLLB 번역 모델의 비상업적 사용 범위도 README에서 확인합니다.

```bash
python -m pip install -r requirements-test.txt
python -B scripts/verify_project.py
docker compose up --build -d
python -B scripts/check_deployment.py --base-url http://127.0.0.1:8000 --ui-url http://127.0.0.1:8501 --real-cases data/quality_benchmark/deployment/real_pdf_cases.json --output outputs/reviewer-deployment.json
```

Compose 실행 중 호스트의 저장소 루트에서 검사 클라이언트를 실행합니다.
작성한 PDF의 다섯 사례와 함께 제공한 원본 PDF의 두 질문을 검사합니다.
UI 검사는 상태 확인 엔드포인트를 대상으로 하며 브라우저 조작은 별도로 검토합니다.

실행 성능을 비교할 때는 같은 논문과 질문, 모델 리비전, 장치 및 설정을
사용합니다. 번역 캐시가 켜진 반복 요청과 캐시를 비운 추론을 구분하고,
초기 모델 로드 시간은 반복 요청 통계에 넣지 않습니다.

## 답변 검토

출력 JSON의 형식 준수와 어휘 마커 충족은 사실 정확도 판정이 아닙니다.
검토자는 원문 페이지와 실제 답변을 함께 확인합니다.

1. 질문에 직접 답하는지 확인합니다. 논문의 다른 사실을 말하는 경우
   관련성이 낮은 답변으로 기록합니다.
2. 목록 항목과 비교 대상, 수치, 단위 및 평가 조건의 누락을 기록합니다.
3. 부정, 적용 범위, 한계와 인과관계가 원문과 일치하는지 확인합니다.
4. 전문용어와 장치 이름이 보존되는지 확인합니다. 원문 용어를 유지한
   표현과 의미가 바뀐 오역을 구분합니다.
5. 인용한 청크와 페이지가 해당 논문에 속하는지 확인하고, 그 위치에서
   답변의 근거를 찾을 수 있는지 기록합니다.
6. 원문에 없는 질문에는 답변 거부, 빈 인용 목록 및 거부 사유가
   함께 반환되는지 확인합니다.

## 남길 기록

실제 검토 일시, 실행한 소스와 설정의 해시, 운영체제와 패키지 버전,
장치, 명령 및 로그를 보존합니다. 질문별 결과에는 질문 ID, 원문 위치,
답변, 사실 일치 여부, 완전성, 인용 적합성 및 실패 설명을 남깁니다.
자동 에이전트가 작성한 기록에는 자동 검토임을 명시합니다.

모든 질문을 검토하지 않았다면 검토 범위와 제외한 질문을 공개합니다.
표본만 확인한 결과를 전체 정확도로 환산하지 않습니다. 실제 검토자의
실행 기록이 생기기 전에는 외부 사용자 검증을 완료로 표시하지 않습니다.
